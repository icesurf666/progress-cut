From 10,000 Frames
to 30 Moments

A coding session produces thousands of near-identical screenshots. Here is how ProgressCut uses perceptual hashing, SSIM, and temporal segmentation to compress hours of work into a 30-second story — without machine learning, without cloud APIs, fully on your machine.

The pipeline

Every second of a recording session produces several frames. After two hours that is anywhere from 8,000 to 14,000 screenshots. The goal is to reduce that to 30 moments that tell the story of what actually happened.

Stage 1 — Deduplication with dHash

Most consecutive frames in a coding session are visually identical — the cursor blinks, the clock ticks, but the code hasn't changed. Keeping these frames wastes memory and pollutes every downstream step.

The solution is difference hashing (dHash): a perceptual fingerprint that captures the gradient structure of an image in 64 bits.

Kernighan's popcount — O(set bits) not O(64)

Computing Hamming distance means counting the differing bits between two 64-bit hashes. The obvious approach loops 64 times. Kernighan's trick loops only as many times as there are set bits — typically 4–12 for near-duplicates. 

export function hammingDistance(a: DHash, b: DHash): number {
  let diff  = a ^ b;      // XOR: 1 where bits differ
  let count = 0;
  while (diff > 0n) {
    diff &= diff - 1n;    // clears the lowest set bit
    count++;
  }
  return count;
}
Why BigInt? JavaScript numbers are IEEE 754 doubles — they cannot safely represent 64-bit integers. BigInt gives exact bitwise arithmetic. The n suffix (0n, 1n) is the BigInt literal syntax.

Stage 2 — Novelty scoring with SSIM

After deduplication we have ~1,200 structurally unique frames. But "unique" doesn't mean "interesting" — typing a few characters passes the dHash threshold but contributes almost nothing to the story. We need a novelty score that measures how much a frame advances the visual narrative.

We use a regional SSIM (Structural Similarity Index) comparison between consecutive frames. Low SSIM = high novelty = candidate moment.

SSIM(x, y) =   (2μxμy + C1) (2σxy + C2)
(μx2 + μy2 + C1) (σx2 + σy2 + C2)
result ∈ [0, 1] — 1 = identical, 0 = completely different

Computing full-image SSIM is expensive. Instead we tile each frame into 16 non-overlapping regions and average the regional scores. This also makes the metric spatially aware — a change in one corner doesn't hide stagnation everywhere else.

Single-pass variance — one loop, not two

The naive SSIM implementation computes the mean in a first pass, then variance in a second. We can eliminate the second pass using the computational formula for variance:

Var(X) = E[X2] − E[X]2
accumulate Σx, Σx², Σy, Σy², Σxy in one loop → compute all statistics afterwards
let sumA=0, sumB=0, sumAA=0, sumBB=0, sumAB=0;
const n = (x1-x0) * (y1-y0);

for (let y=y0; y<y1; y++) {
  for (let x=x0; x<x1; x++) {
    const pa = a.pixels[y*W+x] ?? 0;
    const pb = b.pixels[y*W+x] ?? 0;
    sumA  += pa;   sumB  += pb;
    sumAA += pa*pa; sumBB += pb*pb; sumAB += pa*pb;
  }
}

const muA = sumA/n, muB = sumB/n;
const varA  = sumAA/n - muA*muA;   // Var(X) = E[X²] − E[X]²
const varB  = sumBB/n - muB*muB;
const covAB = sumAB/n - muA*muB;

Stage 3 — Temporal segmentation

A recording session has natural phases: reading, typing, debugging, researching. Long gaps of low novelty are "thinking time" — they shouldn't dominate the story. We partition the frame sequence into activity windows based on the density of high-novelty frames.

What it produces

A 2-hour coding session → 30 moments → a 30-second GIF or MP4 that you can drop into a PR description, tweet, or portfolio. Each moment is held for a duration proportional to how much happened during that segment.
